What the mockups have settled so far

This is a record, not a proposal: it codifies the tokens, type, and components already established across the recipe-page rounds and the nav mockup, so the next round has something fixed to build on instead of rediscovering it each time. Everything below is pulled from the live mockup's actual CSS — nothing here is aspirational.

Decided this round: Bruce loves to cook formally adopts warpedvisions.org's accent family, rebalanced toward orange/red — see Color below
01

Relationship to warpedvisions.org

Bruce loves to cook is a Warped-branded site. Its accent palette is now derived directly from the blog's shipped CSS (warped.css's five flourish-bar hues), not matched by eye — with the hierarchy rebalanced so this property leads with the warm end instead of the blog's blue.

Bruce loves to cook: now

this mockup, current tokens

Same five hues as the blog, same saturation and lightness formula — but re-ordered. Orange leads (interactive, checked ingredients, active nav), red is the emphasis variant (ratios, hovers, CTAs), yellow is secondary (cuisine chips). Blue is demoted to one utility role — the draft flag. Green is held in reserve, unused for now.

Warped Visions — the source

warpedvisions.org — live CSS

Near-grayscale body (#141414 on white) with color banished to one place: a 15px/5px flourish bar pinned to top and bottom, blue-led, running blue→green→yellow→orange→red. Bruce loves to cook inherits the palette, not the layout — see below for where the two now differ.

How the hierarchy was rebuilt

All five warped hues share one saturation/lightness formula (57%/62%) — only the hue rotates: red 14°, orange 34°, yellow 54°, green 151°, blue 210°. The cookbook's tokens are built at those exact hues, re-lightened per role (a darker value reads as text, a pale tint as a fill), and led by orange→red rather than blue. Body copy staying in Lora on both sites was already true before this change and still holds — that throughline is untouched by the palette swap.

Ranked, not flat: accent (orange/red) means "interactive, or teaches you something" — active nav, checked ingredient, Mechanic rail, ratios. highlight (yellow) is descriptive, not interactive — cuisine chips only, so it never competes with the accent for attention. flag (blue) means "unreviewed" — draft banner and inline draft badges; blue reads as "cool, pending" against the warm accent's "hot, active." Green stays out of the UI entirely for now — lowest in the new hierarchy, kept only as a documented option.

03

Type system

Three faces, three jobs. No face does more than one job.

Headings & UI Libre Franklin weights 400–700
Dal Tadka
Section label · stat label · nav
Body & lists Lora shared with warpedvisions.org
Red lentils cook fast and dissolve into a creamy base. The ratio matters: 1 cup lentils to 4–5 cups water. The tadka is not garnish — it's the flavour. Don't skip it.
Quantities & data IBM Plex Mono tabular-nums, always
200g red lentils · 1.2L water · 25 min cook · 1:4–5 ratio

The mono face is load-bearing, not decorative: every quantity, time, and ratio in a recipe is set in it so numbers align visually while scanning an ingredient list mid-cook — the eye can jump straight to the digits without re-parsing prose each time.

Components

Pulled live from the recipe mockup and nav mockup. Each one exists because of the two working principles: recipes teach, and cooking is chaotic.

Ingredient check

Custom flat control, not native chrome, not emoji — 19px target for wet or floury hands mid-cook.

Mechanic callout
A 1:1:1 ratio by volume: mayo, pickle, mustard.

The "context for learning" principle made visible — a recipe with a Mechanic section is teaching a technique, not just listing steps.

Numbered procedure step

06

Open questions for next round

Things flagged across the last three passes that a style guide shouldn't quietly resolve on its own.

?

Borrow the Warped flourish bar itself? Palette is settled now, but the actual top/bottom multicolor strip is a separate, still-open question — a thin version coded by course or cuisine could be a strong signature mark, or the two properties could share the palette but not the layout device.

?

Green is tokenized but has no job. It's the one warped hue not in use anywhere — worth deciding if it stays in reserve indefinitely or gets a real (minor) role, e.g. a vegetarian/vegan indicator.

?

Reference has no real tag coverage (5 of 19 files). Its nav dropdown is a flat shortlist because there's nothing to group by yet — either tag the rest to match the Recipes treatment, or design Reference's nav around its actual shape (flat, chronological, whatever it is).

?

The Food Log and Vlog aren't real sections yet — one file each, no frontmatter, no _index.md. They're in the nav because the folders exist, not because they're ready. Worth deciding if they launch, stay hidden, or get folded into Essays until there's more there.

?

Spacing isn't on a real scale. Section 05 is descriptive, not prescriptive — it's what's accumulated, not a system. Worth collapsing to a proper 4/8px-based scale before more components get built against ad hoc values.

?

Homepage, individual essay/reference layouts, and the light/dark screenshot pass haven't been touched yet — this guide only covers what the recipe and nav mockups have exercised so far.
