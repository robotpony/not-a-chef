Decisions and open questions

  • Reuses the recipe sidebar's frame. An 18.6rem column (10% narrower than the recipe sidebar's 20.7rem, since these modules are denser), the same small-caps section labels, same "after the content in DOM order" placement, and the same top edge: the title block sits above both columns, so the sidebar starts level with the first line of the body. No new visual devices: .search-box, .browse-list, .filter-pill, .section-caveat, and the recipe meta rail's label/value rows.
  • Not sticky. The reference sidebar runs past a screen's height, and a sticky column that can't show its own bottom is worse than a static one.
  • On phones it drops below the article, open, with no toggle. Unlike the recipe sidebar, nothing here is needed while reading. "On this page" is hidden there because Blowfish's collapsible TOC already sits at the top.
  • No section-wide lists. Essay formats and the full reference guide list were cut; they made the sidebar long and repeat what the nav already offers. Modules stay scoped to the page you’re on.
  • No tag lists for essays or reference. Their tags (food-memory, reference) mostly repeat the section, so a tag cloud would be noise. "Cook tonight" uses recipe tags instead, since the point is getting a reader from a story to something to make.
  • Open: should the search box say "Search recipes, essays, guides…" once search indexes more than recipes? It's worded that way here on the assumption it will.
  • Open: backlinks ("Essays that mention this") on recipe pages would be the natural pair to "Recipes in this guide." Out of scope here.
